Relatório Geral de Evolução — A2 DataPoint

Controle de ponto eletrônico com geolocalização, evidência visual, escalas, banco de horas e solicitações.

Cliente/Projeto: Aconchego dos Avós

Responsável: A2 Data

Período: Fases 0 a 5.8/5.8.1

Status geral: Pré-produção / Preparação para homologação

Data: Junho/2026

Resumo Executivo

Este relatório documenta a evolução do projeto A2 DataPoint, que saiu de uma base de dados mockada (experimental) e evoluiu de forma sólida para um sistema real e estruturado de ponto eletrônico corporativo.

Hoje, a plataforma encontra-se operacional com os seguintes pilares já estabelecidos:

  • Login real de administrador protegido por MFA (Microsoft Authenticator).
  • Login funcional do colaborador via matrícula.
  • Escalas de trabalho ativas integradas a registros de ponto com Geolocalização (GPS) e Evidência Visual (Foto).
  • Módulo completo de solicitações (ajustes e justificativas).
  • Apuração completa de Banco de Horas real, com aprovação e reprovação pelo admin.
  • Extrato detalhado de banco de horas para colaboradores.
  • Preparação ativa para a fase de pré-produção, incluindo higienização de todos os dados de testes.
  • Administrador principal registrado sob a Matrícula 01, deixando a plataforma pronta para a entrada do próximo colaborador real (Matrícula 02).

AS IS & TO BE

AS IS — Situação Inicial

No início de sua estruturação, o sistema ainda carregava fortes resquícios arquiteturais do produto anterior (A2 FORM). A plataforma dependia de colaboradores e dados de mock, impossibilitando um fluxo real completo de ponto e auditoria.

  • Não havia fluxo real e completo de marcação de ponto.
  • Ausência de um motor de banco de horas funcional.
  • Não havia validação de evidência visual (câmera) atrelada à entrada e saída.
  • O fluxo de solicitações era inexistente ou incompleto.
  • Nomenclaturas, dados de teste e componentes de design estavam acoplados aos padrões de experimentação.

TO BE — Situação Atual/Projetada

O A2 DataPoint se estabelece agora como um produto robusto e autônomo.

  • Fluxo de dados 100% real operando com o Supabase.
  • Painel de administrador seguro com Autenticação de Múltiplos Fatores (MFA).
  • Controle rigoroso de colaboradores através de Matrícula.
  • Registros precisos de ponto com foto em tempo real e captura de GPS.
  • Módulos completos de Escalas, Banco de Horas e Solicitações (com fluxos de aprovação).
  • Base de dados totalmente higienizada para homologação em ambiente limpo.
  • Organização avançada da arquitetura do projeto para migração ao GitHub e deploy na Vercel.
  • Próxima fase estrategicamente focada em refinamento de arquitetura, melhoria do layout e homologação final com o cliente.

Módulo Funcionalidades Principais

Situação Atual

O sistema atinge o marco final de desenvolvimento das suas principais lógicas de negócio. A base de dados encontra-se quase limpa e voltada totalmente para o período de homologação.

O perfil administrativo "Ricardo" foi preservado com sucesso, recebendo a matrícula 01. A sequência de numeração foi ajustada, assegurando que o próximo colaborador adicionado receba automaticamente a matrícula 02.

Todos os dados espúrios de testes anteriores foram cuidadosamente removidos. Também realizamos as validações pendentes nos repositórios de imagens (Storage) e verificamos que o ambiente mock está adequadamente isolado.

Após a higienização, o ambiente está sendo preparado para a próxima etapa de organização de arquitetura e deploy.

Riscos e Cuidados

Atenção aos seguintes pontos durante a transição para produção:

  • Nunca expor as chaves service_role.
  • Garantir que o arquivo .env.local jamais seja enviado ao GitHub.
  • Manter obrigatoriamente a flag do modo mock desativada em produção.
  • Revisar o dimensionamento do Storage antes do início da homologação.
  • Efetuar a checagem rigorosa das regras RLS antes da entrega definitiva.
  • A câmera e o GPS exigem contexto seguro para funcionar (testes estritamente sob protocolo HTTPS).
  • Fazer a validação com os usuários reais antes de liberar a operação global.

Decisões Importantes

  • O administrador fundador (Ricardo) ocupa permanentemente a Matrícula 01.
  • O login antigo (alias admin) foi preservado por questões de compatibilidade histórica do administrador, enquanto novos colaboradores começam da matrícula 02 em diante.
  • O mock simulado (usuário 123456 / senha 123) está agora controlado com segurança através da variável de ambiente VITE_ENABLE_DEMO_MOCK.
  • Este relatório, bem como a pasta relatorio/, possuem caráter estritamente interno e local, e não serão versionados no GitHub.
  • A Fase 6 marca o início formal do processo de homologação técnica conduzido pela usuária Karol.
