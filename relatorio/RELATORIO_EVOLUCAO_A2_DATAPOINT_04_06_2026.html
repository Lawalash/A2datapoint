Relatório de Evolução — A2 DataPoint

Controle de Ponto por Celular
Cliente: Aconchego dos Avós
Data: 04/06/2026
Este relatório resume o estado de desenvolvimento do sistema A2 DataPoint, focado na organização e no controle do ponto dos colaboradores por celular. O documento detalha as rotinas de segurança, controle de localização e as configurações de horário já estabelecidas.

1. Objetivo do Relatório

Apresentar de forma objetiva como o sistema funcionava no início do projeto, quais melhorias foram desenvolvidas e configuradas na base de dados e quais serão os próximos passos para a conclusão do controle de ponto operacional.

2. Cenário Anterior (Ponto de Partida)

  • O projeto começou como parte de uma solução maior (A2 FORM).
  • A prioridade do cliente mudou para o controle de ponto.
  • O fluxo inicial de marcação era apenas simulado (não usava base de dados permanente).
  • O ponto ainda não contava com autenticação real do colaborador.
  • O colaborador não passava por validação real de localização.
  • Não existia uma regra configurada para impedir ponto fora da escala.
  • Não existia um fluxo administrativo para ativar ou resetar o acesso do funcionário.

3. Cenário Atual

  • O sistema está focado no controle de ponto por celular.
  • O colaborador acessa sua conta usando matrícula e senha.
  • O administrador gerencia os funcionários, as escalas e as configurações gerais.
  • O acesso do colaborador pode ser ativado e resetado pelo administrador.
  • O colaborador só consegue registrar o ponto se cumprir as regras da escala de horário.
  • O registro de entrada e a saída final verificam a localização do colaborador.
  • O sistema permite saídas e retornos de almoço mais ágeis, sem exigir verificação de localização.
  • Os registros de ponto ficam salvos no banco de dados da instituição.

4. Principais Entregas Realizadas

4.1. Isolamento do A2 DataPoint Concluído

  • O sistema foi separado visualmente do escopo clínico. O foco da tela inicial para o funcionário passou a ser apenas o registro de ponto.

4.2. Gestão de Funcionários Concluído

  • Cadastro e listagem de colaboradores.
  • O sistema gera matrículas sequenciais de forma automática.
  • O administrador consegue ativar, inativar e reativar funcionários no sistema.
  • Foi evitada a exclusão definitiva pelo painel para manter o histórico; matrículas antigas não são reutilizadas.

4.3. Gestão de Escalas Concluído

  • O administrador cadastra os horários de entrada, almoço e saída.
  • O colaborador é vinculado a uma escala específica.
  • As escalas podem ser ativadas e inativadas.

4.4. Acesso Seguro do Colaborador Concluído

  • O login é feito exclusivamente com a matrícula numérica e a senha.
  • O administrador ativa o acesso inicial e pode resetar a senha em caso de perda.
  • O sistema obriga a criação de uma nova senha pessoal no primeiro acesso após um reset.
  • Colaboradores inativados perdem o acesso à plataforma.

4.5. Controle por Localização Concluído

  • A entrada e a saída final validam se o celular do colaborador está dentro do perímetro configurado da instituição.
  • Se o colaborador recusar permissão de GPS, o sistema bloqueia o ponto.
  • Se o colaborador estiver fora do raio permitido, o ponto é bloqueado.
  • Distâncias longas são exibidas em quilômetros para facilitar a compreensão.

4.6. Registro de Ponto Concluído

  • Entrada, saída para o almoço, retorno do almoço e saída final são registrados no sistema.
  • As informações permanecem na tela do celular mesmo se a página for atualizada.
  • O sistema evita que um ponto seja registrado duas vezes no mesmo momento.

4.7. Regras e Tolerância de Horário Concluído

  • O ponto só pode ser registrado de acordo com a escala atribuída.
  • O administrador configura minutos de tolerância (janelas permitidas) para bater o ponto.
  • Fora do horário tolerado, o sistema bloqueia o registro.
  • O sistema bloqueia registros em dias de folga do colaborador.

5. Resumo das Regras de Negócio Ativas

  • O colaborador não usa e-mail para acesso, apenas matrícula.
  • Funcionário inativo pelo RH não acessa o sistema.
  • As matrículas antigas ficam preservadas e não podem ser designadas a novos funcionários.
  • As marcações de Entrada e Saída Final exigem localização.
  • As marcações de intervalo (Almoço) não exigem localização, garantindo praticidade.
  • O registro só é liberado nos dias configurados e dentro do horário permitido pelo administrador.
  • A fotografia (em fase futura) será apenas uma evidência visual para auditoria, sem automações de reconhecimento facial.

6. Funcionalidades em Espera

As funcionalidades a seguir serão configuradas e habilitadas em fases futuras:

  • Captura real de fotografia no registro.
  • Armazenamento e visualização das fotos.
  • Contabilização matemática do banco de horas real.
  • Formulários de solicitação de compensação e hora extra.
  • Aprimoramento do painel administrativo para análise do histórico de pontos e relatórios finais.

7. Próximos Passos

  • Ativar a captura de fotos (evidência visual) para a Entrada e Saída Final. Próxima Etapa
  • Ativar o upload das fotos na base de dados.
  • Disponibilizar os registros de ponto da equipe no painel do administrador.
  • Ativar as rotinas de cálculo do banco de horas.
  • Configurar o envio de solicitações de horário da equipe para os gestores.
  • Executar testes práticos diretamente com líderes usando aparelhos celulares variados.
  • Apresentar a funcionalidade completa para homologação do cliente.
Conclusão Operacional O sistema passou da etapa de modelo visual para um ambiente seguro, validando identidade, escalas de horário e controle de localização. A estrutura básica de ponto eletrônico já se encontra operante. O próximo passo será implementar o registro fotográfico e finalizar o painel de leitura para uso do setor de recursos humanos.
